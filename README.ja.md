# JR Cconventional-line Radio Receiver (JR 在来線デジタル列車無線受信アプリ)

[English](README.md) | 日本語

バージョン: **v1.4.0**

Author: KIRISHIKI Yudai <yudai.kirishiki@protonmail.com>

JR 在来線デジタル列車無線を受信する、Rust + Tauri 2 + SoapySDR のデスクトップアプリです。
一つの広帯域 IQ ストリームから **22 波を同時に復調し、各波の音声とデータを独立して復号**します。
製品名・バージョン・Author は、画面下部の「バージョン情報」で確認できます。

## 起動

Rust stable、SoapySDR **0.8 系の開発ライブラリ**と使用する SDR の Soapy モジュール、
[Tauri の OS 別依存ライブラリ](https://v2.tauri.app/start/prerequisites/)を用意してください。
フロントエンドは HTML / CSS / JavaScript なので、アプリのビルド・実行に Node.js や npm は不要です。
UI の開発テストには Node.js 24.15 以降と `npm ci` を使います。

Ubuntu / Debian の例（パッケージ名はディストリビューションにより異なります）：

```sh
sudo apt install build-essential pkg-config libsoapysdr-dev soapysdr-tools \
  libwebkit2gtk-4.1-dev libgtk-3-dev librsvg2-dev libssl-dev
# 使用する機器に合わせ、例として soapysdr-module-rtlsdr 等を追加
cargo run --release -p jr-receiver-desktop
```

受信処理には `--release` を使用してください。`Cargo.lock` を同梱しています。
GitHub Actions で Linux x86_64、Windows x64、macOS Apple Silicon / Intel の GUI・CLI バイナリを生成します。
手動実行は成果物の生成のみ、`v1.4.0` のようなバージョンと一致するタグの push は GitHub Release への公開まで行います。
Windows 版は SoapySDR DLL を同梱し、Linux / macOS はシステムの SoapySDR 0.8 を使用します。
ビルド方法・実行時の依存関係・CI / 公開手順は [リリースガイド](docs/RELEASE.ja.md) を参照してください。
ローカルでのビルド・起動確認は Linux のみで、インストーラーの生成・配布者による署名・公証は行いません。

## 同時受信

設定は [`ui/radio-presets.json`](ui/radio-presets.json) の独自 JSON です。チャンネル定義と受信プロファイルを分離し、
GUI / CLI の組み込みプリセットとして共用します。
デスクトップアプリでは同じ形式の外部 JSON ファイルも読み込めます。外部ファイルの変更に再ビルドは不要です。
外部ファイルは、停止中に「チャンネル一覧」→「プリセットファイル」→「JSON ファイルを選択」から読み込みます。
同じ場所の「再読み込み」で編集を反映し、「組み込みに戻す」で標準の3社へ戻せます。

1. 入力方式を選びます。RTL-TCP を利用する場合は、サーバーの **IP アドレスとポートを入力**します。初回起動時の接続先は空欄です。
   ローカル SDR は「SoapySDR デバイス」に切り替え、「検索」で選択します。
   必要なら詳細設定に SoapySDR 引数、RX 番号、アンテナを指定します。
2. 受信プリセットを選び、受信する波をチェックします。初期状態は JR 東日本の割当22波です。
   **「路線から選ぶ」**はチャンネル一覧を開かずに使えます。路線名・区間の駅名・D番号で検索し、複数区間を選んで周波数を確認してから適用します。受信は「受信を開始」を押して開始します。[路線選択と外部ファイルへの路線情報の追加](docs/ROUTES.ja.md)も参照してください。
   組み込みプロファイルは JR 東日本（22波）・JR 東海（3波）・JR 西日本（19波）の3種類です。各社の割当周波数だけを含みます。
   一覧は **「簡易」表示**が初期値です。周波数・割当・同期状態をタイルで表示し、画面幅に応じて列数を調整します。
   「詳細」に切り替えると、形式・音声件数・データ件数を表で確認できます。切替は受信・録音・選択波・検索条件に影響しません。
3. 中心周波数は **352.603125 MHz**、要求サンプルレートは **240,000 S/s** が初期値です。
   機器が対応するレートに変更できます。SoapySDR は機器から読み戻したレート・中心周波数で帯域を検証します。
   RTL-TCP は設定の読み戻しがないため、要求値を表示して処理に使用します。
   プリセット変更時は対応する中心・推奨レートに切り替えます。東日本・西日本は
   **352.603125 MHz**、東海は **352.625000 MHz**、いずれも **240 kS/s** です。
   IQ WAV 入力の中心周波数はプリセット切替で変更しません。
4. 「受信を開始」で全選択波を処理します。起動だけではサーバーへ接続しません。
   周波数ボタンを選ぶと同期状態、EVM、コンスタレーション、データを表示します。
5. 「音声を聴く」で選択波の音声を再生します。初期状態では **「通話を自動選択」** が有効です。
   同時に通話がある場合は最初に始まった通話を選び、終了後は続いている通話のうち開始が早いものへ切り替えます。
   **周波数ボタンを手動で選ぶと選択を固定**します。「通話を自動選択」にチェックを入れると再開できます。
   非選択波も復号・音声合成を継続します。スピーカー出力は選択した一波です。
6. 「録音・データ保存」の「保存内容・保存先」で、WAV・生フレーム JSONL・データ電文 JSONL を選択できます。
   「保存を開始」で受信中の全波を保存します。初期値は WAV のみです。設定を閉じても状態と開始・停止ボタンを操作できます。

周波数は 352.53750～352.66875 MHz、6.25 kHz 間隔です。
一覧の幅は 131.25 kHz。復調フィルターの余裕を含め、全波の受信には 139.65 kS/s を超える複素サンプルレートが必要です。
実機の有効帯域・アンチエイリアス特性にも余裕を取ってください。
初期値 240 kS/s に非対応の機器では、対応する高いレート（例：1.024 MS/s）を選びます。
ハードウェアのドライバー対応範囲は [SoapySDR](https://github.com/pothosware/SoapySDR/wiki) に従います。

画面上部に受信対象数・現在の同期数・有効データ・音声フレーム・処理欠落をまとめています。
検索は一覧の表示だけを絞り込み、受信対象を変更しません。
チャンネル一覧と選択波モニタは初期状態では折り畳まれています。見出しを開くと、チャンネル選択・受信状態の詳細・再生設定を確認できます。閉じても受信・音声再生・データ更新は継続します。広い画面では運行把握モニタと受信データを横並びにし、上部のリンクから各表示へ移動できます。音声のオン・オフは常に操作でき、受信データには選択中の周波数とチャンネル一覧を開くリンクを表示します。プリセットの読み込み失敗や受信対象の入力エラーでは、必要な設定を自動で開きます。
「更新を一時停止」は選択波の受信データ表示を固定し、
復号処理と運行把握モニタの更新を継続します。狭い画面では一覧をカード形式に並べ替えます。

チャンネル一覧の下の「運行把握モニタ」は、JR東日本の対応する共用波電文から、線区別の遅延数・在線数・遅延階級別件数・最大遅延とその列車番号を表示します。共用波を「一斉」形式で受信対象にしてください。音声の選択・保存の有効無効・受信データ表示の一時停止とは独立して更新します。狭い画面では線区ごとに項目名を添えて表示し、未提供の値は0ではなく「不明」とします。

運行把握電文の日時は、前置部の仕様が判明するまで解釈しません。PCでの最終受信日時のみを日本時間で表示し、IQ WAV再生時には「最終読取日時」と表示します。この日時は情報の作成日時ではなく、現在の運行状況を示すことを保証しません。前置部から情報の経過時間や新旧を判定しません。

分割結合・検証が完了した表を、受信順に一括で反映します。前置部と展開後の表が同一の場合は最終受信日時と受信回数を更新し、いずれかが変わると回数を数え直します。IQ欠落時も直前の完成した表と受信日時を保持します。受信の再開始やプリセット変更では表を消去します。

初期実装の対象は、確認済みの共用波 `0x22 / C9` 形式です。11 byteの前置部とLH5アーカイブを読み、展開後の `0x87` と21 byte×7行を検査します。RS / CRC検証、アーカイブのヘッダー・展開後の検証が必要です。部分的な受信から他の形式を推測しません。

RTL-TCP は IPv4 / IPv6 の IP アドレスを指定します。サンプルレートは 225001–300000 または
900001–3200000 S/s、ゲイン空欄でチューナー自動、数値入力で手動ゲイン、ppm は整数です。
SoapySDR の各種ハードウェア対応はそのまま維持し、RTL-TCP は追加の Rust TCP 入力として実装しています。
サーバー側で生じた IQ 欠落・設定拒否は RTL-TCP から通知されません。画面の「処理欠落」はアプリ内の
ワーカーキュー欠落の合計であり、サーバー側も欠落ゼロという意味ではありません。

## 設定の永続化

デスクトップアプリでは、設定の変更を自動保存し、次回起動時に復元します。

- 入力方式、受信プリセット、中心周波数、サンプルレート、ゲイン。
- 外部プリセットファイルのパス（組み込みを使う場合は未指定）。
- RTL-TCP の IP アドレス・ポート・周波数補正。
- SoapySDR のデバイス引数・RX 番号・アンテナ、IQ WAV のファイルパス。
- 保存の有効・無効、録音・データの保存先、WAV / 生フレーム JSONL / データ電文 JSONL の選択。

保存済みの中心周波数・レートは、起動時にプリセットの初期値で上書きしません。
保存先を選択した結果や、意図的に空欄にした値も記憶します。起動時は設定だけを復元し、受信は開始ボタンで開始します。保存が有効だった場合は、受信準備が整うと自動で保存を再開します。
通常のウィンドウ終了では、入力直後の未完了の設定保存を待ってから閉じます。

設定は Tauri のアプリ設定フォルダーにある `settings.json`（バージョン付き JSON）へ保存します。
標準の場所は次のとおりです。アプリのソースや周波数プリセットには書き込みません。

| OS | 保存場所 |
| --- | --- |
| Linux | `$XDG_CONFIG_HOME/io.jrradio.receiver/settings.json`（未指定時は `~/.config/io.jrradio.receiver/settings.json`） |
| macOS | `~/Library/Application Support/io.jrradio.receiver/settings.json` |
| Windows | `%APPDATA%\io.jrradio.receiver\settings.json` |

書き込みは一時ファイルで完了してから置き換えます。失敗した場合は画面の「保存を再試行」で最新の入力を保存できます。
既存ファイルが破損している、または未対応の設定バージョンの場合は上書きせず、エラーにファイルの場所を表示します。
修正するか退避してから「設定を再読み込み」を選択してください。復元失敗中の入力は自動保存されません。
ブラウザープレビューは永続化の対象外です。

## 通話の自動選択

開始順は最初の有効な音声フレームを基準にし、全波に共通する IQ の時間軸で比較します。
スレッドの実行順では決めません。同期取得に必要な 120 ms 分の判定待ちを設け、同時刻ならプリセットの順で選択します。
音量や PCM の無音では判定せず、有効な音声フレームが **1秒** 途切れたら通話終了と推定します。
短い受信欠落では優先順位を維持し、待機中に終わった通話は飛ばします。IQ 欠落・再同期で通話の状態をリセットします。
選択先へ切り替えたときは直近 600 ms 以内の音声から再生し、待機していた通話全体を後追い再生しません。
この時間制限はチャンネルの選択開始時と非選択波に適用します。同じ波を聴き続けている間は、RTL-TCP から約0.5秒分の入力がまとめて届いた場合も、未再生の PCM を順序どおり保持します。キューの容量は最大5秒のままです。
音声合成の末尾は短い無信号でも出力します。手動選択中は、遅れて届いた自動選択の応答も反映しません。

## 録音・データ保存

受信が「受信中」になったら、「録音・データ保存」で **「保存を開始」**を選択します。
保存を開始すると、アプリを再起動した場合も含め、次回の受信開始後に自動で保存を再開します。受信停止・IQ WAV の終端・アプリ終了では有効設定を維持します。「保存を停止」、または停止中の「保存を無効にする」で無効設定を記憶します。この設定がない従来の設定ファイルでは無効を初期値とします。自動開始に失敗した場合はエラーを表示し、受信を続けます。開始を繰り返し試行することはありません。
「保存内容・保存先」は初期状態では閉じています。開くと WAV / 生フレーム JSONL / データ電文 JSONL、保存先、保存済みフォルダーを確認できます。
保存内容は個別に選択でき、JSONL だけの保存も可能です。変更する場合は一度保存を停止します。
録音状態と開始・停止ボタンは常に表示します。エラー発生時は設定を開き、エラー本文は再び閉じても表示します。
初期保存先は OS のミュージックフォルダー内の `JR Cconventional-line Radio Receiver/Recordings` です。
Windows は既知の Music フォルダー、macOS は `~/Music`、Linux は `XDG_MUSIC_DIR` を使用します。
OS のミュージックフォルダーを取得できない場合は `~/Music` を使用します。
初期保存先が存在しない場合は録音開始時に作成します。画面から既存の別フォルダーを選択・入力することもできます。
初期保存先を取得・作成できない場合は録音欄にエラーを表示し、別の保存先を選べます。
受信対象にチェックした全チャンネルを録音します。表示中の波、検索結果、モニターの消音・音量には依存しません。
「保存を停止」では受信を継続し、受信停止・IQ WAV の再生完了・通常のアプリ終了でも録音を確定します。
停止後は別のフォルダーを選んで録音し直せます。

- 保存形式：**8 kHz・16 bit PCM・モノラル WAV**。開始後に復号・合成された音声が対象です。
- 保存先：選んだフォルダーの下に UTC 日時と重複防止番号を持つ `recording-YYYYMMDDTHHMMSS.sssZ-NNN/` を作成。
  ファイル名は `352537500Hz-000001.wav` のように周波数と連番です。既存ファイルを上書きしません。
- 音声が得られた波だけファイルを作ります。音声がない場合は WAV を作らず、音声件数を 0 と表示します。選択した JSONL と保存情報は残ります。
- 5秒以下の音声フレームの間隔は無音で補い、5秒を超える間隔・再同期・30分の上限で別ファイルにします。
  各 WAV は最初の音声から始まり、受信開始からの連続した実時間録音ではありません。
- `session.json` に設定、`files.jsonl` に確定した各 WAV の周波数・フレーム位置、`result.json` に終了結果を保存します。
- WAV ヘッダーは分割時・停止時に確定します。再生は録音停止後に行ってください。
  録音中と異常終了時は `INCOMPLETE` が残ります。強制終了・電源断時の復旧は自動では行いません。

書き込みは専用スレッド・有界キューで行います。保存が追いつかない場合や書き込みに失敗した場合は、
録音をエラー終了して画面に通知し、受信とモニター再生は継続します。
表示する音声秒数は全チャンネルの PCM の合計で、補った無音や壁時計の経過時間は含みません。

### JSONL の出力

同じ保存フォルダー内に `raw-frames.jsonl` と `data-messages.jsonl` を選択に応じて作成します。
UTF-8、1行1オブジェクトです。約500 msごとと停止時にバッファを出力し、正常終了時にファイルを確定します。
画面の履歴上限・一時停止・重複表示の集約に影響されず、同じ電文の再受信も保存します。

| ファイル | 内容 |
| --- | --- |
| `raw-frames.jsonl` | 同期器が切り出した48バイトの無線フレームを、受信順のまま96桁の `raw_hex` に格納。デスクランブル・訂正前の値を保持し、音声・データの検証に失敗したフレームも含む。IQ サンプルそのものではない。 |
| `data-messages.jsonl` | 復号器が出力した電文ごとの `message`。種別、識別子、送信日時（取得できた場合）、復号した項目、電文の `raw_hex`、フレーム範囲を保持。音声チャンネル情報や未解釈の電文種別も含む。分割電文は組み立て完了時に出力。 |

運行把握電文は `message.kind: "OperationSummary"` と、追加の `message.operation_summary` に出力します。`rows` には `line`（線区）、`delayed`（遅延数）、`on_line`（在線数）、`delay_classes`（3～9分・10～19分・20分以上の順）、`max_delay_min`（最大遅延分）、`train_no`（列車番号）、行の元データ `raw_hex` を格納します。未提供の数値・列車番号はJSONの `null` です。`message.timestamp` は運行把握電文では常にJSONの `null` とし、外側の `received_at` はPCでの復号日時です。未解明の前置部を日時として解釈・検証せず、受信日時による代用もしません。`message.raw_hex` は結合後の圧縮本文、`prefix_hex` は前置部、`expanded_hex` は展開後の表を保持します。`prefix_sum_matches` は観測された加算値との一致だけを示し、一般則が未確定のため、追加の検証済みチェックサムとは扱いません。

両者とも `schema_version: 1`、`received_at`、`channel_id`、`label`、`frequency_hz`、`format`、
`epoch`、`index`、`bit_offset` を持ちます。`received_at` は復号時の PC の UTC 時刻で、送信機の時計ではありません。
`index` はチャンネルの epoch 内の40 msフレーム番号です。`bit_offset` は同期器の区間内ビット位置で、IQ 欠落でリセットされます。
生フレームには `sync_matched`、`marker_errors`、`voice_accepted`、`corrected_bits`（音声受理時のみ数値）も付けます。
電文行の外側のフレーム位置は、その電文を出力したフレームを指します。
各チャンネル内では処理順を保ち、異なるチャンネル間の行順は受信時刻順を保証しません。
`session.json` の `outputs` に保存対象、`result.json` に生フレーム数・電文数・エラーを記録します。
書き込みエラーや保存キューの超過は保存全体を停止し、`INCOMPLETE` と画面のエラーで知らせます。

## IQ 録音の再生と CLI

GUI で入力を「IQ WAV ファイル」にすると、実時間で全選択波を復号します。
ステレオ float32 または PCM16 の RIFF/WAVE、左 I・右 Q、9.6 kS/s～20 MS/s に対応します。
サンプルレートは WAV ヘッダーから取得し、**録音時の中心周波数は手動で指定**します。
RF64、4 GiB を超えて RIFF 長がラップした WAV は受け付けません。通常の RIFF/WAVE に分割・変換してから読み込んでください。

```sh
# SDR 一覧 / 周波数プリセットを JSON 出力
cargo run --release -p jr-receiver -- devices
cargo run --release -p jr-receiver -- presets east

```

出力ディレクトリは新規でなければなりません。周波数ごとに `audio.wav`（8 kHz mono PCM16）、
`data.jsonl`（検証済みメッセージの全受信）、`messages.json`（最新最大 128 件の集約）を保存します。
`decode-frames` の出力は `stream/` 以下の WAV / JSONL とトップレベルの `report.json` です。
先頭・末尾の無音は付加せず、音声フレーム間の欠落は無音として保持します。
同期のビット位相が変わって別ストリームになった場合は連結し、その境界をレポートの epoch で示します。
失敗・中断時は `INCOMPLETE` が残ります。`report.json` には各波の受理・拒否・訂正数と処理時間が入ります。
CLI のファイル復号は読み込みを待たせて欠落を防ぎます。ライブ受信のように実時間を保証するものではありません。

SoapySDR なしでファイル復号と RTL-TCP 入力をビルドすることもできます。

```sh
cargo run --release -p jr-receiver --no-default-features -- --help
```

## 実装と検証

- `crates/jr-conventional-dsp`：DSP、周波数変換・フィルター・タイミング／搬送波同期・等化。
- [`crates/jr-voice`](crates/jr-voice/README.md)：純 Rust の CELP 合成、バージョン 1.2.0。現在・次フレームの合成候補を比較します。先読みは合計 160 ms。固定モデル係数は実行ファイルに内蔵します。
  実際の係数は `src/models/` にあります。
- `crates/receiver-core`：同期、音声チャネル復号、RS / CRC、データ組み立て、LH5、日英テキスト、SoapySDR / RTL-TCP、同時受信ワーカー。
- `src-tauri` / `ui`：日本語 GUI、受信制御、選択波の Web Audio 再生。
- `crates/receiver-cli`：デバイス列挙、RTL-TCP 受信テスト、IQ / フレームファイル復号。

IQ は一回だけ取得し、参照カウント付きバッファを各チャンネルの有界キューへ配信します。
各チャンネルに専用の DSP・同期・音声・データ状態があり、別スレッドで処理します。
ソースのオーバーフロー、キュー欠落を検出すると、該当する連続性を破棄して同期を取り直します。
IQ キューは各波 8 ブロック、TCP 入力はバーストに備えて 32 ブロックです（240 kS/s 時に最大 1.28 秒）。
TCP ヘッダー待ちは最大 3 秒、ストリーム無通信は 5 秒でエラーにし、切断を終了状態と区別します。
UI スナップショットは約 180 ms 間隔、各波のデータ履歴は最大 128 件、音声モニターキューは最大 5 秒です。
リアルタイム再生は 440 ms の揺らぎ吸収用バッファを確保して開始し、画面の詳細表示を更新する前に、音声出力の時計に沿って PCM を連続して再生予約します。到着が少し遅れても再生中の音声を止めません。受信側と音声出力側の時計の差は再生速度を緩やかに調整して補正し（最大 ±0.5%）、まとめて届く入力と画面更新間隔の揺らぎを吸収できるよう、再生予約は最大 1.5 秒に制限します。これらの調整はモニター再生のみに適用し、録音 WAV のサンプルには影響しません。
停止時は取得・処理スレッドを join し、再開時には新しい状態を生成します。
