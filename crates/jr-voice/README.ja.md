# jr_conventional_voice 1.2.0

[English](README.md) | 日本語

純 Rust による RL-CELP 音声合成ライブラリです。
受信アプリは、このクレートの予測器・補正モデル・候補選択付き CELP 合成器を
標準の音声合成処理として使用します。

## デコーダの動作

固定の音響目標モデルが、受信した CELP ペイロードと予測器の出力から、周期性・ピッチ・
スペクトル形状・音量レベルを推定します。候補選択処理では、現在のフレームの3候補と
次のフレームの9候補を実際に PCM へ合成して評価し、選んだ候補の合成状態を引き継ぎます。
推定改善量が設定したマージン以下の場合は、元の選択を維持します。最初のフレームも
元の選択を維持します。チャイムの合成と欠落境界のフェードも、候補の評価に含めます。

モデルの重みはすべて Rust の実行コードに組み込まれます。FEC・CRC に基づくフレームの
受理判定はチャネルデコーダが行い、このクレートはその結果の158ビットのペイロードを
受け取ります。モデルが使用する入力特徴は、RL-CELP の規範的なビット割当を確定する
ものではありません。

連続入力の先読みは **160 ms（40 ms フレーム4個分）**です。連続した有効フレームの
5個目を受け取った時点で、最初の出力が得られます。出力は **8 kHz・モノラル・PCM16 の
320サンプル**で、元のスロット番号を保持します。欠落スロットでは代替音声を作らず、
待機中の処理を進めます。欠落区間の境界で合成状態をリセットし、`flush` により短い通話や
バッファに残った末尾を一度だけ出力します。受信アプリのモニター再生用ジッターバッファは
440 ms です。これは合成の先読みとは別で、保存する音声サンプルには影響しません。

安全な Rust API の `receiver::Voice`、または C ABI **2** を使用できます。
`push()` / `flush()` の後は、その都度 `read()` ですべての出力を読み出してください
（C では `process` / `advance` / `flush` の後）。不受理または非音声のスロットには
`None` を渡します。スロット番号は、有効・欠落の両方を通じて単調増加させてください。
EOF または受信再開後は、新しい `Voice` を作成します。C のステータス構造体は28バイトで、
`jr_voice_version()` はクレートのバージョン `1.2.0` を返します。

## 保守とテスト

- `plan_features.rs`：220要素の特徴抽出と状態履歴。
- `plan_target.rs`：量子化された固定モデルの推論とピッチのリスク表。
- `plan_acoustics.rs`：PCM のピッチ・周期性・スペクトル・音量レベルの評価。
- `planner.rs`：候補の試行合成、状態選択、1フレーム分の先読み。
- `stream.rs`：容量を制限した番号付き入力の管理、欠落処理、チャイムの合成、末尾の出力。
- `src/models/planner_data.rs`：固定の重みと測定用定数。

リポジトリのルートで実行します。

```sh
cargo test -p jr_conventional_voice --locked
cargo clippy -p jr_conventional_voice --all-targets --locked -- -D warnings
```

`tests/planner.rs` は人工的なペイロードをメモリ上で生成し、先読み、短い通話、
欠落スロットと欠落区間、uint32 の最大スロット番号、`flush` の冪等性を確認します。
単体テストでは、C ABI の出力読み出し待ち制御、不正な入力、リセット、内部エラー後の
利用停止、数値の範囲、再現可能なノイズ生成も確認します。これらは API とストリームの
動作を検証するテストであり、音声の再現品質を測定するものではありません。
